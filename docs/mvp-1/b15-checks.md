## Результат

B-15 реализована в экспериментальном API, но **не закрыта**: живой HTTPS-прогон
отложен владельцем в чате до возврата Mac в прежнюю сеть. B-01 проверена вместе
с браузерными DTO и начальным F-02; полный HTTP-контракт остаётся кандидатом.
Бизнес-маршруты `/mvp1` не подключены к runtime. F-07 не входила в эту проверку.

- Общий `shared/session_actions.py` задаёт SessionActionRequest для clear/opened:
  обязательные UUID request_id/expected_session_id; лишние поля запрещены.
  Эксперимент и OpenAPI используют одну модель. Старое тело получает 422.
- После Origin/CSRF backend сверяет живую сессию в синхронной операции без await:
  другая сессия → 409 session_changed, без изменения данных, cookie, revision, TTL.
  При совпадении требуется cookie; без живой сессии clear → 204, opened → 401.
  Старый CSRF отклоняется раньше мутации. Повтор старого clear не удаляет новую сессию.
- Обновлены 14 операций OpenAPI и 37 JSON-примеров, включая тело действий и конфликт.
  Ошибки F-01 имеют `{detail: code}`, кандидат MVP — ApiError 1.1. Эти форматы
  намеренно различаются; предметные Answer/ExecutionAccepted 1.1 не изменены.
- Клиент frontend уже фиксирует намерение до confirm/ожидания Web Lock, сохраняет
  оба ID при retry и обрабатывает session_changed. Дополнительные Chrome-проверки
  подтверждают это на подмене API. Новый F-02 проверен отдельно на HTTP-подменах.

## Продолжение после возврата сети

1. Запустить экспериментальный API/UI по [B-02](session-probe-backend.md#запуск-и-openapi),
   проверить доверенный HTTPS `/f01/ui/`. Использовать отдельный тестовый профиль.
2. Выполнить `.venv/runtime-env/bin/python scripts/check_session_probe.py`:
   пять сценариев с настоящим backend/ingress/UI. Два новых сценария — удержание
   Web Lock во второй вкладке до смены S1 → S2 и потерянный ответ clear с повтором
   первоначальных ID. Они добавлены, но на доступном HTTPS ещё не исполнены.
3. F/QA подтверждают сохранность S2 и её cookie/TTL, необходимость нового
   подтверждения очистки, отсутствие регрессии refresh/reconnect/CSRF.
   После успешного прогона записать результат; только затем закрывать B-15.
   Новое поведение Safari этим не проверено; старое подтверждение владельца
   относится к предыдущей реализации.

Ответы A/F прочитаны. Четыре роли, внешний author вокруг Answer 1.1,
expected_session_id и стартовые brief/beginner/ru повторно не согласовываются.

  квитанций. selected_role для активного выполнения, коды/валидация ролей и

  дня и полноты статистики требуют завершения обсуждения и A-08.

  неизвестного usage, рестарта и очереди — A-09/B-14; утверждённые численные квоты действуют.
- A-07/B-02: аварийный bootstrap до первой cookie, приватный режим, BFCache и
