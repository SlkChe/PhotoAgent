## D-01: проверено

`bash scripts/create_local_tls.sh` выпустил CA и отдельные 90-дневные сертификаты
Dev/Stage. `openssl verify` подтвердил цепочки, serverAuth и DNS-имена.
Контейнерные API/UI собраны и запущены; Dev работает локально через `run_dev.py`.
Владелец переустановил штатный `vmnetd`, после чего Caddy запущен на LAN-порту 443.

`.venv/runtime-env/bin/python scripts/check_https.py` прошёл для обоих адресов:

- HTTPS `/health` возвращает `{"status":"ok"}` с проверкой CA и имени.
- Chrome открывает оба приложения без отключения проверки сертификатов.
- Чат отправляет синтетический вопрос и показывает ответ, WebSocket использует WSS.
- `/sessions`, `/docs`, `/openapi.json` через ingress возвращают 404.

Подтверждена связность Caddy → локальные loopback-сервисы через
`host.docker.internal`, а для Stage — через Docker-сеть. API/UI Stage наружу
не публикуются. Закрытый ключ CA не подключён к ingress.

Для передачи D-01 осталось подтвердить минимальные инфраструктурные требования
экспериментов B-02/B-03 и воспроизводимость запуска участниками; точные адресаты
и результаты — в [журнале решений](decisions.md#передача-участникам-завершение-d-01-и-зависимости-d-02).
Полные F-01/B-02, выбор модели/A-09 и матрица T-07 — последующие профильные работы,
а не автоматические условия закрытия D-01. Доступ с другого устройства LAN
проверяется, если он нужен потребителям стенда. Стенд показывает текущий прототип
и не подтверждает поведение MVP-1. Процедура продления сертификатов ещё не
автоматизирована; их необходимо продлить до истечения 90 дней без замены CA.

## D-05: проверено

Сначала проверен штатный LiteLLM proxy с `docker/test/litellm-proxy.yaml`:
внутренний HTTP `/v1/chat/completions` вернул 200, заданный JSON-текст и числовой
usage 10/20/30. Это фиксированный ответ, не echo последнего сообщения.

Для полного набора сценариев подготовлен кандидат HTTP-обвязки SDK
`docker/test/litellm_mock`. Успешные ответы создаёт `litellm.main.mock_completion`;
некорректные ответы и транспортные отказы задаёт тестовый обработчик. Production
router/облачные completion не используются. Согласование обвязки с backend
и независимая приёмка QA остаются открытыми по условиям D-05.

`.venv/runtime-env/bin/python scripts/check_mock.py`: **6 тестов прошли**.
Проверены последний user.content, usage 100/20/120, детерминированная JSON-фикстура,
сброс/счётчик, 429 с Retry-After, 503, клиентский timeout, повреждённый JSON,
finish_reason=length, отсутствующий/невалидный usage и отказ неизвестной модели.
После перезапуска выполнен успешный повтор набора.
Дополнительно OpenAI SDK из фиксированного тестового образа проверен с
`max_retries=0`: синтетический 429 вызвал `RateLimitError`, счётчик показал ровно
один HTTP-запрос. Это проверка SDK на стенде, не готового адаптера backend.

Mock работает без provider-ключей, с одним worker, UID 10001, read-only rootfs
и временным `/tmp`. В `/proc/net/route` отсутствует маршрут по умолчанию;
TCP-подключения к `1.1.1.1:443` и `8.8.8.8:53` завершились OSError.
Проверки не отправляли данных внешним сервисам. Это проверка сетевой блокировки,
не захват всего трафика. Контейнер имеет только internal-сеть; HTTP-relay публикует
loopback:4000 и проксирует единственный фиксированный upstream.
Обычный Compose не включает mock; без профиля `test` список его сервисов пуст.

Фикстура `tests/fixtures/llm-draft.json` — синтетический кандидат DevOps;
backend должен подтвердить/заменить её для своего черновика генератора.
Нет проверки качества Groq, реальных usage/ошибок и лимитера B-14.

## O-01: проверка AMD64

По отдельному поручению владельца проверен официальный `alpine:3.23.3`, digest
`sha256:25109184c71bdad752c8312a8623239686a9a2071e8825f20acb8f2198c3f659`.
Docker Engine работает на aarch64. Пробный контейнер запущен с явным
`--platform linux/amd64`, без сети, с read-only rootfs, без capabilities
и с `no-new-privileges:true`.

Внутри контейнера: `uname -m` → `x86_64`, `/etc/alpine-release` → `3.23.3`.
Команда `printf abc | sha256sum` дала ожидаемый SHA-256
`ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad`.
Процесс завершился с кодом 0. Контейнер `photoagent-amd64-check` оставлен
остановленным; проверка не меняла сервисы Dev/Stage и не удаляла Docker-ресурсы.

Воспроизведение (без фиксированного имени, чтобы не конфликтовать с первым запуском):

```bash
docker run --platform linux/amd64 --network none --read-only --cap-drop ALL \
  --security-opt no-new-privileges:true \
  alpine:3.23.3@sha256:25109184c71bdad752c8312a8623239686a9a2071e8825f20acb8f2198c3f659 \
  sh -ec 'uname -m; cat /etc/alpine-release; test "$(uname -m)" = x86_64; result=$(printf abc | sha256sum); test "$result" = "ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad  -"; echo OK'
```

Это подтверждает исполнение AMD64-контейнера и базовых команд на текущем Mac.
Сам тест не различает Rosetta и QEMU и не является проверкой производительности
или совместимости всех AMD64-образов. Включение Rosetta подтверждено владельцем.
