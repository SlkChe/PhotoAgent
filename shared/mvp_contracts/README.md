# Предметные модели MVP-1

Схемы 1.1 из [contracts.md](../../docs/mvp-1/contracts.md) размещены отдельно
от `shared/contracts.py`, который обслуживает работающий прототип 0.1.
Новых зависимостей нет. Основные импорты: QueryAnalysis, SearchPlan, Evidence,
Answer, ExecutionAccepted, ExecutionResult и ApiError из `shared.mvp_contracts`.
JSON Schema доступна через `Model.model_json_schema()`; модели совместимы с FastAPI.

Все поля спецификации обязательны, включая nullable; неизвестные поля запрещены.
Валидаторы проверяют граф плана, уникальность ID, внутренние ссылки, виды Answer,
UTC, HTTP/HTTPS URL, локаль и согласованность статусов выполнения.
URL сохраняется точно, без нормализации, чтобы не менять правила карточек источников.

Внешние проверки из `validation.py` вызываются кодом оркестратора:

- `QueryAnalysis.validate_context`: актуальная revision и сущности текущей сессии.
- `validate_plan`: разрешённый реестр, покрытие подвопросов и общий бюджет поиска.
- `validate_evidence`: соответствие вопросу/плану либо режиму reuse.
- `validate_answer`: точное соответствие публичных текстов и метаданных Evidence,
  ограничения частичного поиска, представление спорных версий и наличие Claim в тексте.

Сам факт создания Pydantic-модели не проверяет владение токеном, правила сети/SSRF,
поддержку утверждений по смыслу, право цитирования, соблюдение TTL и токеновой квоты.
Эти проверки остаются у B-04/B-05/B-08/B-09/B-14 и экспертной оценки QA.
Источник доверенного Evidence — backend, не генератор. Передавать между валидаторами
нельзя непроверенные `model_construct`/`model_copy(update=...)` как будто они валидированы.

Часть моделей B-01 реализована; HTTP-маршруты прототипа не переключены на новые схемы.
Полный API, SessionSnapshot и поля ролей/экспорта ожидают A-07/A-13.
Тесты: `tests/contracts_test.py`; OpenAPI проверяется на отдельном тестовом приложении,
а не объявляется контрактом существующих маршрутов прототипа.
