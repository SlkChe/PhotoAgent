# Правила разработки Docker и Compose скриптов и конфигураций

Применяй эти правила при работе с Dockerfile, Docker Compose и развёртыванием независимо от назначенной роли.

- Соблюдай правила безопасности и конфигурации из `.prompts/code-style.md`.
- Для каждого сервиса используй отдельный образ и его `requirements.txt`. Версия Python должна соответствовать стеку проекта.
- Секреты передавай при запуске только тому сервису, которому они нужны. Не записывай их в Dockerfile, Compose, build arguments или слои образа.
- Для локального HTTPS на Mac действует исключение `.devsec/ssl/` из
  `code-style.md`: необходимые серверные ключи подключаются ingress на чтение
  при запуске. Ключ CA и секреты приложения ему не передаются. `.devsec/`
  исключается из всех используемых контекстов сборки; это не хранилище секретов
  приложения Stage/Prod.
- Копируй в образ только необходимые файлы приложения. Проверяй контекст сборки и `.dockerignore`; локальные файлы окружения не должны попадать в образ.
- Конфигурация Compose должна позволять запуск из корня репозитория командами, указанными в `AGENTS.md`. Если файл размещён в `docker/`, явно укажи его путь через `-f` в документированных командах.
- При добавлении конфигурации документируй команды сборки, запуска, остановки и просмотра логов. Проверяй сборку и доступность сервисов перед тем, как сообщать об успешном запуске.
- Перед удалением томов и данных, включая `docker compose down -v`, получай согласование пользователя.
