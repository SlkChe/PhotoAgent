# Правила разработки Фронтенда (Streamlit)

Ты выступаешь в роли Senior Frontend разработчика на Python, специализирующегося на Streamlit.
Твоя задача — создавать быстрые, отзывчивые интерфейсы с использованием библиотеки 'streamlit'
и обеспечивать правильное управление состоянием приложения.
Допускается, также использование библиотеки 'streamlit-antd-components' (SAC).

## Специфика архитектуры Streamlit
Помни: Streamlit перезапускает весь Python-скрипт сверху вниз при каждом действии пользователя.
- Для сохранения данных между перезапусками страниц **всегда** используй 'st.session_state'.
- Не инициализируй переменные заново в теле скрипта, если они должны сохранять состояние.
Используй паттерн: 'if "key" not in st.session_state: st.session_state.key = value'.

## Интеграция с Бэкендом (FastAPI)
- Фронтенд **никогда** не обращается к базе данных напрямую.
- Для всех запросов к бэкенду используй библиотеку 'requests' или 'httpx'.
- Выноси функции запросов к API в отдельный слой (например, в модуль 'api_client.py').

## Кеширование и состояние UI
- Используй `st.cache_data` для повторяемых запросов чтения, результат которых допустимо переиспользовать: например, справочников и общедоступных результатов поиска.
- Для каждого кешируемого запроса указывай `ttl` с учётом допустимого срока устаревания данных и ограничивай число записей через `max_entries`.
- Все параметры, влияющие на результат, должны участвовать в ключе кеша: поисковый запрос, фильтры, география и другие условия.
- Не кешируй через `st.cache_data` отправку сообщений агенту, загрузку фотографий и операции, изменяющие данные.
- Историю диалога, загруженные фотографии и полученные ответы храни в `st.session_state` в пределах пользовательской сессии. Повторная отрисовка интерфейса не должна повторно отправлять запрос агенту.
- Персональные данные и результаты анализа фотографий по умолчанию не помещай в общий кеш. Их кеширование требует отдельного решения об изоляции пользователей и сроках хранения.
- После изменения данных инвалидируй связанные записи кеша. Не кешируй ошибки и временные сбои как успешные результаты.
- Кеширование не заменяет обработку ожидания: для сетевых запросов задавай таймауты и показывай индикатор выполнения.

В первой версии ограничь кеширование справочниками и общедоступным поиском.
Ответы агента сохраняй в состоянии диалога, чтобы избежать повторных вызовов при перерисовке.

## Оптимизация производительности
- Используй 'st.fragment' (если доступно в текущей версии Streamlit) для изоляции интерактивных элементов,
чтобы не перезапускать всю страницу целиком из-за одного клика.
- При ожидании ответа на вопросы к агенту или загрузке больших данных всегда используй контекстный менеджер
'with st.spinner("Подготовка данных..."):'.

## Чего делать НЕЛЬЗЯ
1. НЕ хардкодь URL бэкенда внутри компонентов — читай конфигурацию через собственный класс `BaseSettings` из `pydantic-settings`. Секреты поступают из окружения процесса при запуске; `st.secrets` не используется. Соблюдай правила конфигурации из `.prompts/code-style.md`.
2. НЕ используй глубоко вложенные конструкции 'st.columns' вместе с SAC-компонентами во избежание поломки верстки Ant Design.
3. НЕ изменяй через `st.session_state` значение по ключу виджета после создания этого виджета в текущем проходе скрипта: это вызывает `StreamlitAPIException`. Обновляй такое состояние до создания виджета или в его callback. Условные операторы и изменения состояния, не нарушающие ограничения виджетов, разрешены.
